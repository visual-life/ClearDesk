# ClearDesk 2.1.0 发布说明

发布日期：2026-10-25

## 新增：在线更新

2.1.0 起，ClearDesk 可以自己检查并安装新版本，不必再手动下载 zip、解压、替换。

### 怎么用

- 启动后约 75 秒在后台检查一次（距上次检查不足 12 小时则不再检查，不影响启动速度）。设置 → 关于 → 软件更新 里有 **检查更新** 按钮和 **自动检查更新** 开关。
- 发现新版本时弹出白色对话框，显示版本号和更新说明，按钮：**立即更新** / **稍后提醒**（24 小时后再提示）/ **跳过此版本**（该版本不再提示，更新的版本仍会提示）。
- 点「立即更新」：下载（有进度，网络中断后可从断点继续，自动重试）→ 校验 → 退出 ClearDesk → 替换文件 → 自动重新启动。整个过程不需要管理员权限。

### 更新源

- 默认：`http://101.200.206.248/versions.json`（阿里云轻量服务器，nginx，目前只有 http；域名备案通过、开通 https 后只需改更新源，无需改程序，见下）。
- 服务器不可达时回退到 GitHub Releases 接口；GitHub 回退只提示新版本并打开下载页，不自动安装（除非该 Release 附带了已签名的 `versions.json`）。
- 更换更新源的三种方式（优先级从高到低）：
  1. 设置 → 关于 → 软件更新 → 更新源（填完整的 `.../versions.json` 地址或站点地址，「恢复默认」清空）。
  2. 配置文件 `%LOCALAPPDATA%\ClearDesk\update-source.json`（其次是安装文件夹里的同名文件）：`{"sources":["https://example.com/versions.json"],"github":true}`。
  3. 服务器侧：已签名的 `versions.json` 里可带 `updateUrl`（新的主地址）和 `mirrors`（备用地址列表）。客户端只接受签名通过的清单里的这两个字段，并记住它们——所以将来换域名，只要在旧服务器上发布一次带 `updateUrl` 的签名清单，已安装的客户端就会自动迁移。

### 安全

- 更新包必须带 ECDSA P-256 / SHA-256 签名：`versions.json` 的 `signature` 签的是 版本号、文件名、大小、SHA-256、`updateUrl`、`mirrors`。公钥编译在 ClearDesk.exe 里，私钥只在发布者的电脑上（`C:\work\update-keys\`），不会上传服务器、不进 Git、不进发布包。
- 因此即使服务器只有 http，中间人或被入侵的服务器也无法让客户端安装未经签名的程序；签名缺失、错误、版本号不比当前新（防回滚攻击）、大小或 SHA-256 不符，一律拒绝，并提示原因。
- 安装包自带 `SHA256SUMS.txt`，解压到暂存目录后逐个文件校验；拒绝路径穿越（`..`、绝对路径）、检查 ClearDesk.exe 的文件头和大小上限。
- 说明：http 下更新说明、发布日期不受签名保护（可能被篡改显示内容，但不影响安装什么）；检查更新会向更新服务器发送一个普通 HTTP 请求（含 User-Agent `ClearDesk/版本号`），不上传设置或文件信息。

### 替换过程与回滚

- 由一份临时目录里的 ClearDesk.exe（`--apply-update`）执行：等待 ClearDesk、`--guard` 守护进程和 TranslucentTB 退出（若上次异常退出导致任务栏仍被隐藏，先恢复）→ 先把旧文件改名为 `.cdold-*`（正在使用的 DLL 也可以）再放入新文件，相同的文件跳过，ClearDesk.exe 和 SHA256SUMS.txt 最后替换 → 重新用原来的参数启动 → 观察 4 秒，若新版立即崩溃则自动回滚并重启旧版。
- 更新过程记录在 `%LOCALAPPDATA%\ClearDesk\update\journal.json`；更新中途断电或崩溃，下次启动会自动回滚。旧版本完整备份在 `%LOCALAPPDATA%\ClearDesk\update\backup\<旧版本>`。
- 用户数据（`%LOCALAPPDATA%\ClearDesk` 下的设置、歌词缓存，以及安装文件夹里的 `update-source.json`、`startup-error.txt`）不会被覆盖。
- 开机自启动：启动项指向的 ClearDesk.exe 路径不变（原地替换），更新后自启动继续有效。（2.0.9 的启动项自动修复仍在。）
- 安装文件夹不可写（例如装在 `C:\Program Files`）时，不会尝试提权，而是提示改为手动更新或把 ClearDesk 放到可写位置。从压缩包里直接运行时也不能在线更新。

### 局限

- 2.1.0 是第一个带更新功能的版本，2.0.9 及以前需要手动升级一次。
- 当前只有 http 下载；在备案和 https 就绪前，安全性依赖签名。
- 没有增量更新，每次下载完整 zip（约 6 MB）。

## 测试

- `Self`：新增版本号比较（含预发布、构建元数据）、清单解析与签名载荷、签名校验（篡改、缺失、错误密钥）、SHA-256、更新源优先级、重定向与镜像、续传、包校验与路径穿越、替换顺序、回滚等检查。
- `Regression`：异步部分——本地 HTTP 服务模拟断点续传、重试、SHA-256/大小不符、GitHub 回退、对话框和设置页控件。
- 端到端 `scripts/test-update.ps1`：用一次性密钥签名，在临时文件夹里复制一份 2.1.0，由本地测试服务器提供伪造的 2.1.1（同源码改版本号），真实走完 检查 → 下载（首个源不可达、下载中途被切断后续传）→ 验证 → 替换 → 重启；并验证：被篡改 / 未签名 / 回放旧版本的清单被拒绝、包内文件与校验表不符被拒绝、文件被占用导致替换失败时回滚、新版立即崩溃时回滚、`updateUrl`/`mirrors` 重定向。脚本断言 HKCU 的 Run 启动项没有被改动，且不触碰任何真实安装文件夹。

## 发布者流程

`scripts/publish-update.ps1`（签名密钥由 `scripts/new-update-key.ps1` 生成一次）：给定 zip 与更新说明，计算大小和 SHA-256，签名，生成 `versions.json` 和更新说明页面，打印上传命令。先上传 zip，最后上传 `versions.json`；用 `-Verify http://服务器/` 复核线上清单的签名和 zip 的大小、哈希。
