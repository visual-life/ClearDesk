# ClearDesk 2.0.9 发布说明

发布日期：2026-10-24

## 修复：开机自启动不生效

有用户反馈“登录后自动启动”开了也不启动。2.0.9 针对下面几种原因逐一处理（设置里的开关位置不变：设置 → 常规 → 登录后自动启动）。

| 原因 | 现象 | 2.0.9 的处理 |
|---|---|---|
| 启动项路径失效 | 升级时解压到新文件夹并删除/改名旧文件夹，启动项仍指向旧路径；设置里仍显示“已开启”，开机却没有任何反应 | 每次启动自动检查并改为当前这份；也会把指向更旧版本（如 1.9.1）的启动项更新到新版；缺引号、缺 `--startup` 的旧写法一并修正。已手动关闭的不会被重新打开 |
| 被 Windows / 安全软件禁用 | “设置 → 应用 → 启动”或任务管理器里把 ClearDesk 关了，注册表里的启动项还在，旧版仍显示开启 | 设置里显示“被 Windows 禁用”，旁边新增「启动应用设置」按钮，直接打开 Windows 启动应用页；在 ClearDesk 里重新勾选会同时解除禁用标记 |
| 从压缩包里直接运行 | 没解压就双击 zip 里的 ClearDesk.exe，程序在临时目录运行，重启后目录消失 | 此时无法开启自启动，并提示先解压到固定位置 |
| 下载标记 | GitHub 下载的 zip 解压后，文件带“来自 Internet”标记，登录时可能被 SmartScreen 等拦住 | 开启自启动或自动修复时，清除 ClearDesk 自己文件夹内文件的该标记 |
| 注册表被拦截 | 安全软件阻止或还原 Run 启动项 | 写入后回读校验，失败则改用“启动”文件夹快捷方式 |
| 登录时桌面尚未就绪 | 任务栏/桌面窗口还没创建好就启动 | 等待任务栏和桌面就绪（最多 30 秒，已就绪则不等待）；工作目录固定为程序所在文件夹 |
| 重复启动 | 旧、新两个启动项同时存在时弹出“已在运行”或设置窗口 | 登录启动的重复实例静默退出 |

## 排查建议

- 把整个 zip 解压到固定位置（例如 `D:\ClearDesk`），从那里运行一次，再在设置里开启自启动。
- 设置里状态为“被 Windows 禁用”时，点「启动应用设置」，把 ClearDesk 打开。
- 失败原因会写入 `%LOCALAPPDATA%\ClearDesk\errors.log` 和 `startup-error.txt`。
