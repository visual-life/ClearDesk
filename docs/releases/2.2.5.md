# ClearDesk 2.2.5 发布说明（2026-10-30）

本版包含 6 项内容：文件夹映射组件、设备电量组件、「显示桌面」不再收起组件、减少 360 误报、TB-04（开机时 TranslucentTB.exe 被占用）修复，以及测试实例不再干扰正在使用的 ClearDesk。下文区分**已实测**和**推断**。

## 1. 新组件「文件夹映射」

用法：桌面右键 → ClearDesk 新建组件 → 文件夹映射 → 选择文件夹。

- **显示**：文件和子文件夹以 系统图标 + 名称 显示。文件夹排在前面，按自然顺序排序（file2 在 file10 前面）。默认不显示隐藏文件和系统文件，右键可以切换。最多显示 600 项，超出时会提示。
- **大小和位置**：宽度、高度都可以自由调整，图标会自动重新排列；位置可以自由拖动。
- **打开**：双击打开文件或文件夹。
- **右键菜单**：都是白色 Win11 风格。
  - 每一项的菜单：打开 / 在资源管理器中显示 / 复制路径。
  - 组件的菜单：刷新、图标大小（大 / 中 / 小）、显示隐藏文件、在资源管理器中打开、选择文件夹…，还有所有组件通用的「无边框 / 透明背景」和「自定义背景」。
- **实时更新**：用 FileSystemWatcher 监视文件夹，内容变化后 0.3 秒刷新。文件夹被删除或断开时会显示提示，之后每 5 秒检查一次，文件夹恢复后自动重新监视。
- **滚动**：用鼠标滚轮滚动，不显示滚动条。
- **多开**：可以放多个，每个记住自己的文件夹（`widgets\folder*.json`）。
- **新建位置**：新建时出现在鼠标右键的位置。
- **安全**：ClearDesk 不会修改文件夹里的任何东西。
- **已实测**：列表、排序、隐藏文件、新建 / 删除文件自动出现 / 消失、宽度变化后重新排列、高度可调、多实例 ID、菜单项、滚动条隐藏。

## 2. 新组件「设备电量」

用法：桌面右键 → ClearDesk 新建组件 → 设备电量。

**读取方式**（只读，不安装任何驱动或厂商软件）：

1. **蓝牙设备**：读取 Windows 自己显示的电量，也就是「设置 → 蓝牙和设备」里的那个值（DEVPKEY_Bluetooth_Battery）。
2. **标准 HID 电量报告**：HID Usage Page 0x06 Battery Strength，或 0x85 RemainingCapacity。很多 2.4G 接收器和耳机用这种方式报告。
3. **罗技 HID++ 2.0**：适用于 VID 046D 的 Unifying / Lightspeed / Bolt 接收器，以及直连的罗技设备。
   - 读取顺序：0x1004 Unified Battery → 0x1000 Battery Status → 0x1001 Battery Voltage。
   - 只发送查询类请求（查功能号、读状态、读名称），不改设备的任何设置。
   - 只报告电压的设备会显示「电压 x.xx V」，**不换算成百分比**。

**显示规则**：

- 读不到的设备显示「不支持读取电量」，并说明原因。**绝不显示估算或假的数据**。
- 宽高可以自由调整；每列至少 200 px，按宽度自动分成多列。

**右键菜单**：

- 白色 Win11 风格，包括立即刷新、显示 / 隐藏不支持的设备、无边框、自定义背景。
- 「低电量提示」**默认关闭**。开启后，电量低于 20% 且没在充电时提示一次。

**轮询**：每 60 秒在后台线程读一次。

**诊断**：运行 `ClearDesk.exe --battery-diag`，会生成 battery-diag.txt，列出每个设备的结果和尝试过程。

**本机实测**（2026-10-30）：

| 设备 | 结果 |
|---|---|
| 罗技 PRO X 2（Lightspeed 接收器 046D:C54D） | **77%**（HID++ 0x1004）。后来几次读取时设备已休眠或关闭，显示「接收器上没有设备应答」，没有显示旧值 |
| 2.4G Wireless Device（25A7:2420） | 不支持读取电量（没有标准 HID 电量报告，可能是厂商私有协议） |
| 罗技 USB Receiver（046D:C539） | 接收器上没有设备应答（配对的设备当时关机、休眠或未配对） |
| 蓝牙 | 本机只有 MediaTek 蓝牙适配器，没有已连接的蓝牙设备，**蓝牙路径没能实测** |

## 3. Win+D / 任务栏「显示桌面」不再收起组件

**原因（已实测）**：在本机用 COM 调用 `Shell.Application.ToggleDesktop`（与 Win+D 和「显示桌面」按钮的效果相同，没有发送按键）。显示桌面时，资源管理器把桌面窗口 Progman 提到第 8 层，组件在第 34 / 39 层，被压在下面，看起来就像「收起来了」。

**做法**：

- 新的 DesktopKeeper 监视前台窗口切换（EVENT_SYSTEM_FOREGROUND），另外每 0.4 秒检查一次桌面窗口是否压住了组件。
- 一旦压住，就把组件临时提到桌面窗口上方（置顶，不抢焦点）。
- 切换回其他程序后，组件放回底层，锁定的组件重新固定在最底层，PositionGuard 和位置保存不受影响。
- Dock 和启动台不参与这个机制，它们原本就保持显示。用户自己设为置顶的组件也不动。

**实测**（同一台电脑，外部 ToggleDesktop）：

| 情况 | 组件所在层 | Progman 所在层 | 结果 |
|---|---|---|---|
| 关掉 keeper（即 2.2.4 的行为） | 34 / 39 | 8 | 组件被压住 |
| 2.2.5 | 3 / 8 | 13 | 组件可见 |

恢复后提升 1 次、放回 1 次，锁定的组件回到底层，组件位置没变，测试结束后桌面已恢复。

**另外**：在测试进程内调用 ToggleDesktop 时，资源管理器有时不响应，因为正在使用的电脑前台会变。所以回归测试里这一项按「组件不在桌面窗口下面」来判断，另加 Raise / Lower 流程测试。

**没有覆盖到**：真实按下 Win+D 键，按要求没有发送按键；多显示器。

## 4. 减少 360 误报

**改动**：

- **不再把其他程序打包进 exe**。2.2.4 的 ClearDesk.exe 内嵌了 TranslucentTB 的 5 个 exe / dll（「携带并释放其他 PE 文件」是典型的木马 dropper 特征）。2.2.5 把出厂副本移到 exe 旁边的 `taskbar-factory.zip`，exe 里只保留它的 SHA-256 清单。exe 从约 3.6 MB 降到约 1.9 MB。zip 只有在清单与编译进 exe 的清单完全一致、并且自检通过时才会使用。
- **完整的版本信息**：公司 visual-life、产品 ClearDesk、文件说明、版权、文件版本 2.2.5.0。manifest 增加了说明，并补齐 Windows 10/11 的 supportedOS。
- **不做单文件打包，不混淆**：本来就没有使用单文件打包；没有混淆，也没有加壳。

**仍然存在、但有正当理由的行为**：

| 行为 | 用途 |
|---|---|
| 开机自启动（HKCU Run，用户在设置里开启） | 让 ClearDesk 登录后自动运行 |
| 透明任务栏组件 TranslucentTB 会向资源管理器注入 ExplorerTAP.dll | 这是 TranslucentTB 本身的工作方式，签名者 Charles Milette |
| 在线更新器替换自己的文件 | 更新前校验签名和 SHA-256 |
| 测试代码编译在 exe 里，包括本地 HTTP 测试服务器 | 只在带 `--*-test` 参数时运行 |

**这些都是推断**：360 的具体检测规则不公开，无法确认改完一定不再报，需要用 360 实测。

**根本办法是代码签名证书**：用 OV / EV 代码签名证书签名 ClearDesk.exe 和 zip 里的其他 exe，信誉会随签名积累。EV 证书通常一开始信誉就较好。本版**没有购买任何证书**。

### 360 误报申诉方法

1. 打开 360 开放平台的「软件误报反馈」：https://open.soft.360.cn/report.php 。说明页：https://www.360.cn/n/10454.html 。
2. 需要提交：
   - 被报毒的文件：ClearDesk.exe，或整个 `ClearDesk-2.2.5.zip`。不超过 512 MB，不能加密。
   - 360 报毒界面的截图，要能看到病毒名。
   - 手机号和短信验证码、邮箱，QQ 可选。
   - 样本来源说明，200 字以内，例如：「开源桌面整理工具 ClearDesk 2.2.5，作者 visual-life，下载地址 http://101.200.206.248/ 或 GitHub 发布页，无捆绑、无联网上传，SHA256：<zip 的 SHA256>」。
3. 一般 1–2 个工作日会有结果。也可以发邮件到 opensoft@360.cn。
4. 长期做法：在 open.soft.360.cn 注册开发者账号，每次发版前提交新版本做检测、加白。

## 5. TB-04：开机时 TranslucentTB.exe 被占用 / 读不了

**用户日志里的「无签名」（已实测原因）**：2.2.4 在文件被独占锁住时，WinVerifyTrust 返回 TRUST_E_NOSIGNATURE，于是被显示成「无签名」。

- 本机把真实的 TranslucentTB.exe 独占锁住后：2.2.4 的 `--taskbar-diag` 显示「签名 无签名」，2.2.5 显示「未知（文件读不了…不代表没有签名）」。
- 用户日志里文件大小是 1,436,672 字节，与出厂文件（880,528 字节）不同。原因**没有查明**：可能是别的 TranslucentTB 版本，比如商店版或自己下载的版本。2.2.5 的诊断会列出每个正在运行的 TranslucentTB 的路径（包括商店版），下次能看清楚。

**改动**：

- **静默重试**：遇到「被占用」时，按 1、2、4、8、15、30 秒退避重试，**期间不弹提示**。每次重试都记录到时间线，并用 Restart Manager 查出占用文件的进程。
- **共享方式读取**：读取文件时用 FileShare.ReadWrite|Delete。
- **已经在运行就视为正常**：TranslucentTB 已经从 ClearDesk 自己的组件文件夹（或备用目录）运行时，直接视为正常并接管，不再校验正在使用的文件。在别处运行的副本（包括商店版）会在提示里写出路径（TB-07）。
- **改用备用目录**：重试用完后，不动被占用的文件，把出厂副本（没有出厂副本时用完好备份）静默释放到 `%LOCALAPPDATA%\ClearDesk\taskbar-run`，校验后从那里启动。
- **提示区分原因**：只有备用目录也失败时才提示一次。提示标题区分「组件文件被占用 [TB-04]」和「组件文件内容与出厂清单不一致 [TB-03]」，正文写明「这不是文件内容不一致」。
- **`--taskbar-diag` 新增内容**：
  - 正在运行的 TranslucentTB 副本（自己的文件夹 / 商店版 / 其他位置）；
  - 每个文件在约 3 秒内多次尝试读取的结果和占用进程；
  - 出厂副本里 exe 的签名、版本和大小；
  - 「未知」与「无签名」的区别说明；
  - 开机重试时间线（`taskbar-timeline.txt`）。

**已实测**：

- 独占锁住后：判为 TB-04，不是 TB-03，签名显示「未知」。
- Restart Manager 能查出占用文件的进程。
- 静默重试期间托盘提示计数是 0。
- 重试用完后能从备用目录启动，被锁的文件哈希和修改时间都没变。
- 接管自己文件夹里正在运行的副本。
- 商店版路径能正确分类。
- 真正失败时只提示一次，内容是「被占用」。

## 6. 测试实例不再干扰正在使用的 ClearDesk（开发中发现的问题）

开发期间，用户收到了一条真实的 TB-04 提示，占用者显示为测试用的 ClearDesk。这是测试进程在模拟「真正失败」时弹出了托盘提示。

**修复**：

- **测试 / 预览运行不弹托盘提示**：带 `--*-test` 或 `--preview` 参数时只计数，不显示。
- **只让一个 ClearDesk 管理任务栏**：用会话内的命名互斥量 `Local\ClearDesk.TaskbarManager.main`。其他 ClearDesk 不启动第二份 TranslucentTB，也不提示，每 30 秒再看一次。测试和预览按各自的数据目录使用不同的互斥量名，不会抢用户实例的。
- **被其他 ClearDesk 占用视为正常**：占用者是另一个 ClearDesk，或者它启动的 TranslucentTB 时，视为正常，不提示，也不再启动第二份。
- **测试隔离**：测试实例使用独立的数据目录（`artifacts\…\preview-data`）和临时组件目录，测完会关掉自己启动的进程。测试前后都核对过，用户正在运行的 2.2.2 实例（PID 20028 / 20348，TranslucentTB 13632）和开机自启动项都没有被改动。
