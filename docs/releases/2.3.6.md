# ClearDesk 2.3.6

2.3.6 修的是「托盘图标」页面里少了图标的问题：QQ 已经被收进「^ 显示隐藏的图标」，页面标题只写「托盘图标 · 6」，列表里没有 QQ，点刷新也没用。

## 原因（在你这台电脑上实际读到的）

- Windows 11 的「^」隐藏图标面板里一共有 6 个图标（UI Automation 里都是 AutomationId = `NotifyItemIcon` 的按钮）：ClearDesk、网易UU远程、YueLink、NVIDIA 设置、联想智能引擎，和**第 6 个——名称是空的**（就是 QQNT，`C:\Program Files\Tencent\QQNT\QQ.exe`）。任务栏上还有 1 个可见图标（ChatGPT）。
- QQ 的托盘图标有时没有提示文字（tooltip），UI Automation 给它的名称就是空字符串。
- 2.3.3 到 2.3.5 的读取代码里有一句 `if (name.Length == 0) continue;`，把名称为空的图标整个丢掉。所以页面上是 1 个可见 + 5 个有名字的隐藏图标 = 6 个，QQ 是第 7 个，永远出不来；刷新只是重新读一遍，同样丢掉。
- 此外还有三个会让图标「消失」或点错的小问题：图标一律靠名称区分（两个同名图标、名称为空的图标无法区分，点击也找不到）；一次读取失败会把已经记住的被收起图标清空；打开隐藏面板后只看一眼就读，面板里的图标还没出齐时会少读。

## 修复

1. **每个图标都会列出来，不再按名称丢弃**：UI Automation 里所有 `NotifyItemIcon` 都算（不再依赖按钮的类名），可见的和被收起的都一样；没有任何数量上限。
2. **名称为空的图标自动起名**，顺序：图标自己的提示文字 → Windows 记录的这个程序（`HKCU\Control Panel\NotifyIconSettings`）的初始提示文字 → 程序文件的「文件说明 / 产品名称」→ 程序的文件名。哪个程序对应这个图标，靠两条线索判断：① 已经有名字的图标所属的程序、没在运行的程序、explorer 都排除，剩下的候选里按图标图片对比（取亮度花纹和颜色一起比，QQ 换皮肤、换状态图标颜色也认得出来）；② 只剩一个候选就是它。还认不出来的显示为「未命名图标」（多个时「未命名图标 1、2…」）——**也不会丢**。
3. **同名图标、无名图标都各自保留**：每个图标有「名称 + 第几个」的身份，页面行、缓存、左键 / 双击 / 右键（UI Automation ShowContextMenu）都按这个身份找到它，点第二个无名图标不会点到第一个。
4. **刷新真的重新读取并替换旧缓存**：成功读到的结果整个替换已记住的列表（已经不存在的图标会消失，新出现的会出现，包括没有名字的）；真的没有被收起的图标时，列表就是空的。读取失败（面板没打开）时**保留**之前记住的图标并提示，不会清空。读取失败时自动重试一次。
5. **等面板稳定再读**：点开「^」面板后，等图标出现并且连续 3 次看到的数量一样（最长 4 秒）才读取。
6. 缓存文件多存「原始名称」「序号」「程序路径」；旧版缓存继续能读。

## 测试

- 新增 `V236Tests`：用模拟的 UI Automation 结果测过滤 / 去重 / 起名：6 个图标里第 6 个名称为空；同名图标；多个无名图标；空列表；起名三级回退；候选程序的排除；图片对比（颜色、形状、两个候选一样时不乱猜、没有候选时给「未命名图标」）；页面刷新替换旧缓存、读取失败保留、缓存带身份重启；点击第二个无名行对应序号 1。
- 真实程序：两个托盘图标**提示文字为空**的测试程序（`--tray-helper @empty`），读取后两个都在列表里、名称非空、key 不同，点其中一个只会到达对应的程序。
- 全部测试集（Self / Regression / ClientLyrics / LyricsLive / UpdateE2E）结果见包里的 `*-test.txt`。

## 其他

- 只读诊断：`ClearDesk.exe --tray-diag236 输出文件` 会把「托盘图标」页现在会列出的图标（原始名称、起名结果、候选程序和图片得分）写到文件里，不点击任何图标；读取被收起的图标时会像页面一样把「^」面板短暂打开再关上。
- 版本号统一为 2.3.6。外壳右键菜单包未改动（2.2.9.0），无需重新「一键启用」。
- 2.3.5 的桌面图标、「^」面板恢复机制都保留。

## 已知限制

- 图标图片匹配是根据 Windows 保存的程序图标截图推断的：程序更换了图标、或同时有多个同样图标的程序时，宁可显示「未命名图标」也不乱猜；这个名字只影响显示，点击仍然作用在你点的那一行对应的那个图标上。
