# 开发说明

## 目录

| 目录 | 内容 |
| --- | --- |
| `src/` | 应用入口、桌面组件、Dock、启动台及 Windows 接口 |
| `tests/` | 桌面回归、独立窗口夹具与合成性能测试 |
| `assets/` | 图标 PNG 与多尺寸 ICO |
| `config/` | Windows manifest 与 .NET 运行时配置 |
| `scripts/` | 依赖准备、测试运行器及编译器校验值 |
| `third_party/` | 农历源代码和可选组件的许可证、配置及摘要 |
| `dist/` | 本地编译产物，Git 忽略 |
| `artifacts/` | 隔离的测试程序、测试配置和结果，Git 忽略 |

当前项目保持单一 C# 编译入口，`build.ps1` 直接调用 Roslyn。测试代码与程序一起编译，通过显式命令行参数运行，普通启动不执行测试。

音乐会话的编译依赖 Windows 10/11 SDK（17763 或更新）。构建脚本自动查找本机 SDK；也可通过 `-WindowsMetadata '...\Windows.winmd'` 指定。最终用户无需安装 SDK。

## 验证范围

`Self` 验证配置序列化、农历、天气映射和基本 Windows 接口。非交互式环境可能无法发现桌面或注册钩子，日志会标注信息或限制。

`Regression` 验证收纳布局、滚动、材质切换、Dock 显隐、窗口生命周期、固定／取消固定、启动台透明和外部点击等。结果依赖本机桌面引用数量，不能用固定 PASS 数量作为跨机器标准。

音乐回归使用可控会话提供者，验证明确选择、命令目标、拒绝请求、断开清理、切换时过期回包和关闭时释放。真实客户端的集成记录见 [音乐连接说明](MUSIC.md)，不能用模拟回归替代客户端验证。

`PopupBenchmark` 连续打开启动台，记录打开调用、首次渲染回调、布局稳定状态及渲染回调间隔。它使用测试模式，排除了全局外部点击监听；不是端到端用户体验或显示帧率测试。

交互回归应在单独的 Windows 桌面会话进行。测试会启动并关闭自有夹具窗口，不关闭用户应用。测试目录包含本机路径和图标引用，不能提交到 Git。

## 可选任务栏组件

首次准备可联网下载官方固定版本；离线准备允许传入完整发行包的 `taskbar` 目录。两条路径都验证 EXE/DLL 和上游源码压缩包摘要，并保留 GPL 许可证。不要修改摘要来掩盖未知来源的组件替换。

## 1.8.0 自动天气和新增交互

`Regression` 新增可控天气传输测试：缓存／并发、文化无关坐标、错误数据、取消、禁用联网、失联保留上次天气和组件关闭。文件新建、同名保护、路径限制、发送引用、重新启用收纳、拖动输入排除、隐藏刷新、实际应用正常关闭／取消关闭也纳入回归。

运行 `.\scripts\test.ps1 -Suite WeatherLive` 会访问 **ipwho.is** 获取公网 IP 对应城市，并向 **api.open-meteo.com** 发送四舍五入到小数点后两位的城市坐标。仅在明确允许这两项联网访问后执行；不包含在默认回归或 CI 中。日志只记录通过／失败，不输出城市、IP 或坐标。

天气网络配置依据 [Microsoft .NET TLS 建议](https://learn.microsoft.com/en-us/dotnet/framework/network-programming/tls)：允许操作系统协商协议并启用强加密，未禁用证书验证。

Dock 的缓存测量使用两个独立测试窗口：比较首次读取和连续 12 次刷新中的窗口属性读取数量，并记录每次耗时。此测试验证重复查询减少，不等同于整个应用 CPU／内存下降比例；性能因实际窗口数量和系统环境而异。
